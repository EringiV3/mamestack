# 設計書

## 選定

保存のない静的サイトなので、規則どおり Astro にする。

採用は Astro。アプリケーション用の Void は使わない。保存が「なし」で始まるため、ゲートも Astro 以外を拒む。

このサンプルの `site/index.html` は、Astro が出力する一枚の静的ページの代わりである。工場リポジトリの中で検証動画を録るために、`npm create astro` の対話的な生成はしていない。本番のプロダクトでは `npm create astro@latest` でサイトを作り、この HTML と同じ文言を `src/pages/index.astro` に置く。UI フレームワークは足さない。開閉はページ内の数行の script だけにする。

## 構成

一画面。サーバー処理は無い。クライアント JS は「今日焼いたパン」の開閉だけ。

## 画面

- v1 の「本日の営業時間を表示」: 店名、8:00–15:00、水曜定休。パンの一覧は閉じたまま。
- v1 の「今日焼いたパンを開閉する」: ボタンで三つの名前が開き、もう一度で閉じる。
- 店主がスマホから売り切れを更新する画面は作らない。

## データ

無し。D1 も KV も R2 も作らない。

## 性能

営業時間は HTML に書く。フォントは環境にある日本語のゴシックを指定し、外部フォントを取りに行かない。画像は置かない。

## デプロイ

コマンドは `cf deploy`。Wrangler は使わない。

Cloudflare の "Deploy your first Worker"（2026-11-03 に確認）は、Astro 6 以降を `cf` ベータでビルドできない、と書いている。npm の Astro はその日 `7.4.5` だった。したがってこの設計の公開コマンドは、公式が制限を取り下げるまで実行しない。詳細は工場の `docs/cloudflare-deploy.md`。

ホスティングの意図は Cloudflare Workers の静的アセットである。独自ドメインは v1 では付けない。`worker.domains` は、付けると決めた日に公式の `cloudflare.config.ts` を見てから書く。

## マイルストーン

v1。T1 と T2 の検証動画が揃ったあと、デプロイは skip とする。理由は、このサンプルが Cloudflare アカウントを持たず、Astro と `cf` の組み合わせが公式の未対応のままだから。

## 未検証

- `cf deploy` がこの静的 HTML、または将来の Astro 成果物を公開できること。
- 独自ドメインを買う CLI。
